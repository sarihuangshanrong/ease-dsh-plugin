# 06_UTILS_LIBRARIES.md 生成规范

本文件保留现有名称以兼容下游引用，但正文定位升级为“共享能力与依赖治理”。目标是解释复用边界、供应链风险和升级策略，而不是枚举所有 util 方法。

## 1. 输入索引

读取 `utils_index`、`module_index`、`ownership_index`、`decision_index`、`architecture_analysis_index` 和构建/锁文件。依赖版本以实际解析或锁定结果优先，声明版本与解析版本冲突时并列记录。

## 2. 必需章节

### 2.1 文档范围与基线

记录 commit、语言生态、扫描到的构建/锁文件、生成代码和排除范围。

### 2.2 共享能力总览

按能力而非目录罗列复用内容，例如身份、序列化、时间、错误、可观测性、数据访问。每项说明提供方、消费者、公共契约、owner 和复用边界。

### 2.3 内部可复用组件

只深度说明跨模块引用或架构影响显著的组件。记录稳定 ID、用途、主要入口、线程/状态特征、错误语义、消费者和证据。不得凭主观判断称为“高质量代码”。

### 2.4 外部依赖治理

每个关键依赖记录用途、声明版本、解析版本、使用模块、替代难度、许可证、SBOM 来源、已知漏洞扫描来源和升级约束。未执行安全扫描时写“未知”，不得声称无漏洞。

### 2.5 横切机制

说明真正影响系统行为的注解、常量、异常包装、拦截器、序列化器和公共配置。普通常量或简单包装无需进入正文，可保留在索引。

### 2.6 依赖中心性与演进约束

用实际 import/build/call 图说明高 fan-in 共享能力的消费者、公共契约、横切行为和替换接缝。区分结构中心性、运行时关键性和供应链锁定；高引用次数本身不等于性能瓶颈或坏设计。记录升级时需要共同发布、数据/协议迁移或回归验证的边界。

### 2.7 升级、废弃与替代策略

记录弃用 API、版本冲突、重复能力、维护状态、升级测试入口、兼容性风险和替代候选。没有批准替代方案时只记录候选，不作架构决策。

### 2.8 风险与待确认

标记无 owner 共享库、循环依赖、全局可变状态、过期依赖、许可证未知、SBOM/漏洞状态未知和错误语义不一致。

## 3. 内容质量要求

- 正文聚焦共享能力与架构影响；完整类/依赖清单留在索引
- 复用频次必须来自调用/导入统计，不凭目录名推断
- 许可证、SBOM、漏洞状态必须带工具或清单证据
- 示例代码仅用于解释已有公共契约，不复制大段实现
- 关键共享能力必须说明失效/行为变化的爆炸半径，以及替换或升级受哪些消费者和兼容接缝约束
