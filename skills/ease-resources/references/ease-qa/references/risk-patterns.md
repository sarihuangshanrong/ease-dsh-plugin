# 风险模式与知识维护

以下是教学风险模式，**不是当前项目已有缺陷**。按触发信号使用，不全部套用。

## QA-R01：响应失败，副作用已经成功

- **信号**：外部调用、超时、自动重试、幂等键。
- **机制**：提交成功与响应送达不是原子事件，调用者将未知误判为失败并重复操作。
- **后果**：重复退款、订单、通知或消息副作用。
- **最小反例**：提交后丢弃响应，再以相同业务标识重试。
- **判定依据**：业务确认的重复操作语义、金额约束或副作用次数，不擅自要求所有动作只执行一次。
- **验证**：检查真实提交点、幂等持久化、查询/恢复路径；Mock 返回成功不足以证明机制正确。
- **边界**：已确认可重复且无有害副作用的动作不强制增加幂等存储。

## QA-R02：并发检查通过，写入后突破约束

- **信号**：先查询余额/库存/次数，再写入；共享数据。
- **机制**：多个请求读取同一旧状态，各自通过局部检查。
- **后果**：超卖、超额退款、重复领取、丢失更新。
- **最小反例**：两个请求在检查后、写入前交错执行。
- **判定依据**：已确认的不变量和事务语义；不得自创余额或业务上限。
- **验证**：受控并发与真实持久层约束，检查最终状态及各请求结果。
- **边界**：只有本地不可共享纯计算时，不要求数据库并发实验。

## QA-R03：当前测试全绿，旧消费者失效

- **信号**：接口字段、枚举、序列化、数据库迁移、滚动部署。
- **机制**：只测新生产者与新消费者，忽略部署过程与回滚组合。
- **后果**：部分实例或旧客户端出错，回滚无法恢复。
- **最小反例**：旧消费者读取新增枚举，或回滚后的旧代码读取迁移数据。
- **判定依据**：明确支持的版本窗口和兼容承诺。
- **验证**：契约、混合版本、数据兼容与恢复证据。
- **边界**：已获批准的破坏性升级按其迁移方案验证，不要求永久兼容。

## QA-R04：测试预期复制实现错误

- **信号**：测试调用同一计算函数生成 expected；只验证非空；过度 Mock。
- **机制**：实际与预期共享错误来源，测试无法区分正确和错误实现。
- **后果**：错误金额、权限、排序等持续绿灯。
- **最小反例**：改错关键条件或舍入后，测试仍通过。
- **判定依据**：独立规则实例、批准契约或经确认的不变量。
- **验证**：边界实例和有效断言，必要时最小变异实验；不为追求数量制造变异。
- **边界**：共享无业务语义的 fixture 工具本身不构成循环 oracle。

## QA-R05：多份材料一致，但遗漏同一需求

- **信号**：设计、案例与实现映射都来自同一份缩减后的需求摘要。
- **机制**：生产者漏列分母，下游完全对齐错误全集。
- **后果**：100%追溯仍缺业务要求。
- **最小反例**：从原始需求恢复一条没有进入任何下游清单的义务。
- **判定依据**：当前权威需求与已确认变更，不纳入已撤销要求。
- **验证**：独立恢复全集并双向对账；探索验证需有真实质量来源。
- **边界**：无来源的新增愿望不当作漏做功能。

## 候选知识如何沉淀

### 其他按需风险视角

| 触发信号 | 失败机制与最小反例 | 判定依据与边界 |
|---|---|---|
| 身份、角色、资源归属变化 | 授权遗漏；用另一用户访问同一资源，检查所有可达入口 | 已确认权限规则；先检查统一鉴权，不能只凭局部缺检查报错 |
| 删除、过期、迁移与恢复 | 数据和业务状态脱节；恢复旧副本后已删除对象再次可见 | 已确认生命周期与恢复承诺；不擅自规定保留期限 |
| 用户操作中断或错误输入 | 结果不明、无法恢复；提交后断线再返回，用户不能确定是否成功 | 用户任务与交互要求；不把个人界面偏好当缺陷 |
| 故障与恢复依赖人工判断 | 错误无法定位或恢复；部分失败后无法确定受影响对象 | 明确的可观测与恢复目标；不强制无关场景使用特定监控工具 |

这些视角按信号选择，不转成每次必查项。验证方法应匹配相应机制，而不是重复套用退款示例。

### 三类原因与最小改进

真实缺陷分别分析：**产生原因**（错误机制）、**逃逸原因**（为什么验证没发现）、**扩大原因**（为什么未及时发现、隔离或恢复）。每类都附依据，资料不足就列假设和验证方式，不强行填全。

例如重复退款：幂等状态与副作用不一致可能导致错误；只测连续重试可能导致漏检；缺少重复退款识别可能扩大损失。分别需要实现控制、故障场景验证和发现/恢复措施，不能统一写成“多加测试”。这是教学假设，不代表真实事故根因。

选择能发现原问题的最小改进，验证有效并评估误报与成本后再推广。知识卡保留：`适用信号 / 机制与后果 / 最小反例 / 判定依据 / 验证方法 / 来源 / 不适用条件 / 候选或已验证 / 维护与复核信息`。

未验证推测标为候选。一次故障不自动变成普适规则；不要为了模板编造根因或知识条目。重复模式用链接关联，避免每个任务复制相同知识。

业务事实由业务责任方确认，测试案例由相应维护者管理。本 skill 默认只返回候选知识，不自动改写业务规则、测试案例或全局验收要求。
