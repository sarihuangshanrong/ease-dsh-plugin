# 深入判断方法

按遇到的问题选用以下内容，不要求每次建立所有模型或使用所有技术。基本职责、结论规则和停止条件以入口为准。

## 从交付物选择观察视角

| 对象 | 优先追问 |
|---|---|
| 需求 | 谁需要什么结果？规则、异常、边界和成功标准是否明确？ |
| 设计 | 关键约束如何保证？部分失败能否被观察并恢复？ |
| 测试方案 | 是否覆盖状态、调用者和受影响旧行为？预期如何成立？ |
| 实现与交付证据 | 结果是否兑现要求，能否发现关键错误，版本与环境是否一致？ |
| 缺陷反馈 | 错误怎样产生、为何漏检、为何扩大影响？ |

## 用模型定位遗漏

风险写成“触发条件 → 失效机制 → 错误状态 → 用户后果”。优先考虑后果、暴露范围、可恢复性和已有控制，不仅凭模块类型定级，不编造发生概率。

| 模型 | 要看什么 | 常见遗漏 |
|---|---|---|
| 业务与状态 | 角色、状态、允许和禁止的操作 | 终态操作、越权、重复事件、冲突规则 |
| 数据与所有权 | 谁写谁读、事务、唯一性与生命周期 | 精度、丢失更新、并发突破约束 |
| 依赖与时序 | 提交、响应、重试与恢复的关系 | 部分成功、重复副作用、乱序、补偿失败 |
| 变更与影响 | 新旧行为、调用者、配置及部署组合 | 旧客户端、间接依赖、混合版本回归 |

## 让验证方法匹配风险

| 风险特征 | 方法与重点 |
|---|---|
| 阈值、范围、精度 | 等价类和边界值；检查两侧、舍入、空值、极值 |
| 多条件规则 | 判定表和条件组合；检查优先级、冲突及遗漏 |
| 生命周期 | 状态转换；检查禁止转换、重复事件和终态 |
| 并发、重试 | 受控时序和故障场景；检查原子性及部分成功 |
| 接口、部署兼容 | 契约和混合版本验证；检查旧消费者与回滚兼容 |
| 性能、恢复 | 基线、负载和恢复验证；检查量级、饱和与恢复目标 |
| 未知区域 | 有目标的探索；记录问题、边界和观察结果 |

方法应能区分正确实现与可信的错误实现。技术数量、案例总数和异常比例不能替代风险覆盖；不为凑数量增加检查。

## 证据难以判断时

- **判定依据独立吗？** 测试若用被测函数生成预期，可能复制实现错误。使用批准规则、独立实例或已确认不变量；旧系统输出也可能有错。
- **证据支持同一主张吗？** 成功响应不证明副作用正确；Mock 单测不能单独证明真实事务或跨系统恢复。hash 只能说明内容一致。
- **多份证据真的独立吗？** 设计、案例和报告若都来自遗漏了一条规则的摘要，彼此一致也不完整。回查原始依据。
- **反例具有区分力吗？** 缺少局部鉴权时先检查可信入口、统一鉴权和可达旁路；已有控制覆盖该路径就撤回，控制未知则报告证据缺口。
- **结果可重复吗？** 留意顺序、真实时间、共享状态和隐含环境。一次成功不等于故障机制已排除。

难以给出精确预期时，可检查经确认的不变量或输入变换关系，并说明局限。例如金额总额守恒不能单独证明每个收款人的分配正确。

## 处理相似但不同的情况

| 情况 | 应区分的判断 |
|---|---|
| 完整方案确认没有必要并发场景／只拿到部分测试摘要 | 前者是验证方案缺陷；后者无法判断方案是否完整，不能把“未提供”当“不存在” |
| 已有可信失败反例，同时缺少其他运行结果 | 保留缺陷结论，另列未知；不能让不确定性掩盖已确认问题 |
| 只改说明文字／改变被测行为、配置或环境 | 前者不必否定原证据；后者检查对质量主张的影响并建议定向重验 |
| 范围外的改进偏好／范围外的可信重大风险 | 前者不影响验收；后者独立提示来源和后果，由调用方决定是否扩展 |

影响不明时说明限制，不全盘否定或沿用旧结论。严重性取决于后果和暴露，置信度取决于证据，两者不要混为一谈。
