# 03_API_INTERFACE.md 生成规范

本规范用于生成协议无关的集成契约文档。接口既包括系统提供的能力，也包括系统消费的外部能力；不得只扫描 Controller 或限定为 HTTP/RMB。

## 1. 输入索引

读取 `api_index`、`integration_index`、`module_index`、`security_index`、`decision_index` 和 `architecture_analysis_index`。按项目实际技术栈发现 HTTP、RPC、GraphQL、消息/事件、Webhook、CLI、Job、文件交换等协议。

## 2. 必需章节

### 2.1 文档范围与基线

记录 commit、扫描范围、已识别协议、未覆盖的生成代码或外部契约。

### 2.2 协议与契约总览

按协议汇总提供方接口、消费方接口、入口数量、外部消费者/提供者和证据覆盖率。不存在的协议不生成空的固定章节。

### 2.3 提供的接口

每个提供方接口至少记录：稳定 ID、协议、操作标识、路径/topic/serviceId/command、归属模块、实现 symbol、请求/事件和响应类型、认证授权、错误语义、版本、状态、已知消费者和来源证据。

同时记录幂等、超时、重试、速率限制或背压语义；未发现时写“未发现实现证据”，不得补默认值。

### 2.4 消费的接口

每个消费方接口记录调用方、外部提供者、目标标识、调用目的、超时、重试、熔断/降级、认证方式和失败影响。动态地址无法解析时保留表达式和配置来源，不伪造最终地址。

### 2.5 数据契约与错误语义

- 引用 DTO/schema/proto，而不是生成与源码无关的“标准响应示例”
- 区分业务错误、校验错误、权限错误、依赖错误和未知错误
- 记录 nullable、枚举、约束、消息 key、顺序性和重复投递语义的实际证据

### 2.6 端到端调用语义与故障传播

按关键调用链描述同步/异步边界、扇出、调用预算、超时层级、重试放大、背压、隔离、降级和恢复入口。只有配置存在时写“配置了超时/重试”，有链路或测试证据后才能说明端到端效果。标出时间耦合、严格顺序和共同上线要求。

### 2.7 安全、可靠性与兼容性

汇总认证、授权、敏感字段、幂等、超时、重试、限流、版本化、兼容性和废弃策略。配置与代码冲突时并列记录。

### 2.8 风险与待确认

标记匿名敏感接口、无超时外调、无限重试、契约漂移、未知消费者、缺少版本策略和无法解析的动态路由。

## 3. 内容质量要求

- 接口发现必须以实际框架信号为准，框架规则写入索引的 `detector`
- 接口详情的关键标识、请求类型、响应类型和安全语义分别绑定证据
- Markdown 正文用于架构摘要与关键契约；全量清单保存在外置索引并链接
- 消息或 RPC 的同步/异步语义必须由调用方式证明，不按协议名称推定
- 对架构显著调用链必须说明依赖故障如何传播、哪里被隔离以及是否存在重试/超时预算放大
