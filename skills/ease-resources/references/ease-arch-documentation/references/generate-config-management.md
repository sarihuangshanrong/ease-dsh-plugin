# 05_CONFIG_MANAGEMENT.md 生成规范

本规范用于说明配置如何定义、加载、覆盖、保护、变更和回滚。只记录 key、结构和来源；不得输出真实 secret、token、密码或完整连接串。

## 1. 输入索引

读取 `config_index`、`runtime_index`、`security_index`、`ownership_index`、`decision_index` 和 `architecture_analysis_index`。扫描项目实际存在的配置格式、配置中心、环境注入、启动参数、容器/IaC 和代码绑定方式。

## 2. 必需章节

### 2.1 文档范围与基线

记录 commit、环境/部署单元范围、扫描到的配置来源和无法读取的外部配置中心。

### 2.2 配置来源与优先级

给出实际加载链和覆盖顺序，例如文件、环境变量、启动参数、配置中心；只有实现或官方框架配置能证明优先级。记录动态刷新和启动时固定配置的边界。

### 2.3 环境差异

从实际 profile、overlay、values 或部署清单发现环境，不预设 dev/sit/uat/prd。只比较 key 是否存在、来源和结构差异，不展示敏感值。

### 2.4 核心配置目录

每项记录稳定 ID、key/prefix、用途、类型、默认值是否存在、必填性、owner、作用域、重启/热更新要求和证据。默认值含敏感信息时仅写 `[REDACTED]`。

### 2.5 Secret 与访问控制

识别 Secret Manager、KMS、密文解密组件、文件权限、环境注入和访问审计。不得默认使用 RSA 或任何固定加密方案；未发现保护机制时标记风险。

### 2.6 配置控制面与失效半径

说明配置由谁发布、哪些运行单元读取、传播是一致还是分批、失效会影响哪些能力/租户/数据，以及是否存在最后已知良好值、隔离或停止传播机制。动态配置中心故障、解析失败和部分实例刷新不一致分别分析。

### 2.7 变更、校验与回滚

记录配置校验、发布方式、灰度、动态刷新、审计、失败回滚和重新加载行为。说明错误配置的影响范围和可观察信号。

### 2.8 风险与待确认

标记明文 secret、危险默认值、环境漂移、无 owner 配置、无校验动态刷新、无法回滚配置和文档化但未被代码消费的 key。

## 3. 内容质量要求

- 敏感值一律不落盘；示例也不得使用看似真实的地址、账号或密文
- “加密”“访问受控”“可热更新”等结论必须有机制证据
- 配置目录正文按架构影响排序，全量 key 保存在 `config_index`
- 同一 key 多来源冲突时展示来源链，不擅自选择有效值
- 架构显著配置必须给出传播路径、执行点和失效半径；“支持热更新”不等于更新具备原子性或可回滚性
