# 04_DATA_MODEL.md 生成规范

本规范用于说明数据存储、所有权、关系、流转、一致性和生命周期。它不是单纯的 DDL 抄录。

## 1. 输入索引

读取 `schema_index`、`data_flow_index`、`module_index`、`security_index`、`runtime_index`、`decision_index` 和 `architecture_analysis_index`。证据可来自 DDL、迁移脚本、ORM、Mapper、查询、数据管道、备份/IaC 配置和批准的数据规范。

## 2. 必需章节

### 2.1 文档范围与基线

记录数据库/Schema/集合范围、commit、扫描目录、DDL 与运行态覆盖限制。

### 2.2 数据存储与所有权总览

列出实际存储类型、逻辑数据域、读写模块、owner 和共享方式。区分共享数据库、独立 Schema 与跨系统复制。

### 2.3 核心数据模型

- ER 图只包含可证明的实体和关系
- 区分物理外键、逻辑关联和推导关系
- 核心表记录主键、关键约束、索引、owner、来源和用途
- 全量字段清单留在 `schema_index`；正文突出核心字段和架构约束

### 2.4 数据流与血缘

说明数据从哪里产生、经过哪些模块或接口、落到哪里、被哪些下游消费。跨系统复制、批处理和消息同步必须标注方向与频率证据。

### 2.5 数据不变量与关键写路径

从入口到持久化说明核心状态变更的校验、事务、并发控制、事件/副作用和成功确认点。每条数据不变量记录执行约束、绕过路径、违规后果与验证方式；共享表多写方必须分别列出写路径。

### 2.6 一致性与事务

记录事务边界、隔离级别、锁、乐观版本、幂等键、最终一致性、补偿和重放机制。`version` 或 `update_time` 只能证明并发/审计线索，不能作为备份证据。

### 2.7 数据分类分级与保护

按项目已有规范标记敏感性、PII、加密、脱敏、访问控制和审计。没有分类规则时标记待确认，不自行创造等级。

### 2.8 生命周期、保留与归档

记录创建、更新、删除、软删除、归档、保留期和清理任务的实际实现或批准策略。

### 2.9 备份、恢复与迁移

备份与恢复结论只接受备份作业、数据库平台配置、IaC、运行手册或批准策略作为证据。记录迁移工具、版本顺序、回滚限制；RPO/RTO 无证据时不得给出数值。

### 2.10 风险与待确认

标记无 owner 数据、共享表写入、缺少约束、敏感数据裸露、不可回滚迁移、未知保留策略和无法证明的逻辑关系。

## 3. 内容质量要求

- 不把字段名或代码注释自动提升为已确认业务定义
- 推导关系必须列出 join/查询证据并标为 `inferred`
- 不在文档中输出真实敏感数据样例
- 表清单完整度由外置索引验证，正文以架构重要性排序
- 核心写路径必须标出状态提交点、事务外副作用、失败后可重试/补偿/人工恢复入口及证据缺口
